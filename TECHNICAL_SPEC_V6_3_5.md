# Техническое задание V6.3.5

## Цель

Создать стабильный режим «Фото на модели», в котором исходный макет является главным источником изделия и принта, а фото-референс используется только для сцены, позы, камеры, света и кадрирования.

## Обязательные блокировки

1. Тип изделия, сторона печати, цвет, фактура, крой и силуэт берутся из исходного макета.
2. Принт нельзя переписывать, сокращать, упрощать, переводить, заменять или увеличивать ради выразительности.
3. При отдельном PNG он является главным источником всех пикселей принта.
4. Фото-референс не может менять цвет, крой, тип изделия, размер принта или его содержание.
5. Недавно использованные референсы исключаются из первичного подбора.

## Контроль после генерации

Перед отправкой в Telegram готовый результат сравнивается с:

- исходным макетом;
- отдельным принтом, если он был загружен;
- выбранным фото-референсом.

Проверяются:

- тип изделия;
- сторона печати;
- точность цвета;
- точность кроя и силуэта;
- точность принта;
- размер и положение принта;
- соответствие композиции референсу;
- отсутствие старого принта из референса;
- отсутствие самовольных изменений сцены.

Результат с недостаточным баллом не отправляется в Telegram. Причина сохраняется в `/check`.

## Переменные окружения

```env
MOCKUP_POSTCHECK_ENABLED=true
MOCKUP_POSTCHECK_REQUIRED=true
MOCKUP_POSTCHECK_MIN_SCORE=82
MOCKUP_POSTCHECK_TIMEOUT_SECONDS=120
```

## Поведение при ошибке проверки

Если изображение уже создано, но сервис контроля временно не ответил, файл сохраняется в базе как ожидающий ручной отправки. Новый платный запрос автоматически не запускается.

## Критерии приемки

- неправильный тип изделия или сторона всегда блокируются;
- принт с сильным искажением блокируется;
- заметно неверный цвет или крой блокируются;
- результат с чужим принтом из референса блокируется;
- повтор одного и того же референса снижен за счет истории и перемешивания подходящих кандидатов;
- `/check` показывает общий балл, принт, цвет, крой и причину отклонения.
